# countersign-pool

Building large pools of Korean words that are hard to mishear, for spoken
challenge/response countersigns. Abstract: [abstract.pdf](abstract.pdf).

The pipeline takes common nouns from a subtitle corpus, describes each word by the
articulatory features of its pronounced form, links words that are closer than a
threshold τ in a confusability graph, and picks a large independent set of that
graph as the pool. Pool size is traded against τ; τ is set at the knee of N(τ).
Distances and pools are checked against confusions produced by two independent
text-to-speech → speech-recognition channels in noise.

## Results (x = 5%)

| | |
|---|---|
| candidate words | 20,262 (2–3 syllables) |
| distance | Manhattan on syllable-slot feature vectors |
| knee τ* | 7 (edge if distance ≤ 6) |
| pool | 6,536 words, 12.67 bits (upper bound 7,262) |
| in-pool confusion at −5 dB (held-out channel) | 0.80 optimized / 0.85 random / 0.90 most frequent |

Full write-up with figures: [runs_manhattan/report/report.md](runs_manhattan/report/report.md).
The earlier edit-distance pipeline is kept for comparison in [runs/report/report.md](runs/report/report.md).

## Layout

```
cpool/                library
  lexicon.py          corpus -> Kiwi NNG lemmas -> 2-3 syllables -> Zipf cutoff per x
  g2p.py              g2pk2 surface forms
  phonetics.py        articulatory features, weighted edit distance (numba)
  vectors.py          fixed-length syllable-slot vectors; Manhattan / Euclidean / cosine
  calibration.py      binomial GLM for the edit-distance weights, re-alignment loop
  channel.py          TTS -> noise at a given SNR -> forced-choice ASR listener
  graph.py            components, CP-SAT exact MIS, greedy / forest / no-swap heuristics, knee
  stats.py            bootstrap helpers
scripts/              one script per stage (below)
tests/                unit tests
config.yaml           edit-distance pipeline   -> runs/
config_manhattan.yaml Manhattan pipeline       -> runs_manhattan/
colab_*.ipynb         notebooks used for the GPU (Whisper) stages
```

## Stages

| script | what it does |
|---|---|
| `s1_lexicon.py` | candidate sets for x = 5, 10, 50 |
| `s2_calibration.py [--section calibration_v2]` | fit edit-distance weights on the original channel |
| `s3_distances.py` | edge list for the chosen metric |
| `s4_metric_validation.py` | closest vs random pairs (edit-distance pipeline) |
| `s8_metric_selection.py [--channel heldout]` | compare the four distances on one shared pair set |
| `s5_grid.py` | all (x, τ) cells, knees, final pools |
| `s6_pool_validation.py` | pools vs random / most-frequent baselines on the held-out channel |
| `s7_report.py`, `s9_report_manhattan.py` | figures, tables, report |
| `pilot_heldout.py` | choice of the held-out ASR |
| `make_colab.py`, `make_abstract.py` | Colab bundle and notebooks; abstract PDF |

Run with `CS_CONFIG=config_manhattan.yaml` for the Manhattan pipeline (default is
`config.yaml`). Every stage writes `runs*/<stage>/` with a `manifest.json` (config hash,
package versions). Stages that use a listening channel cache TTS audio and trials, so
reruns resume.

```
pip install -r requirements.txt
python -m pytest tests
python scripts/s1_lexicon.py
...
```

Whisper on CPU is very slow; the original-channel stages were run on a Colab T4
(`colab_metric_selection.ipynb`). The held-out channel (gTTS → SenseVoice-Small) runs on CPU.

## Data

Not included; place in `data/raw/` (checksums are in `config.yaml`):

- `ko_full.txt`: Korean OpenSubtitles 2018 frequency list from
  [hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords) (`content/2018/ko/ko_full.txt`).
- `nikl2003.txt`: National Institute of Korean Language, *Korean learner vocabulary list* (2003), tab-separated.

`runs*/lexicon/` contains word lists and frequencies derived from these sources.

## Not included

Audio/trial cache and distance matrices (`runs*/cache`, `runs*/distances/*.npz`): regenerated by the stages.
